# Supabase Profiles Implementation Plan

Goal: independent verified-email profiles with persistent local study data and safe cross-device sync.
Architecture: per-owner IndexedDB cache, entity records, Supabase Auth and RLS, conditional RPC writes, three-way reconciliation.
Tech: React, TypeScript, supabase-js, PostgreSQL; existing GitHub Pages deployment.
Spec: ../specs/2026-11-19-profiles-design.md

## Constraints
Preserve legacy data. Never bundle secrets. Remain on GitHub Pages. No paid service activation. Keep audio and detailed Anki history local and owner-scoped.

## Review focus
Offline edit/delete conflicts; login switch during async work; empty/cloud-first accounts; oversized initial imports; unavailable auth/configuration/network.

## Implementation sequence
1. Add entity packing/reconciliation and tests for independent edits, same-field conflicts, tombstones, counters and unknown fields. Commit the sync domain.
2. Add PostgreSQL migration: owner RLS, monotonic revisions, conditional batch RPC, bounded input. Verify using PostgreSQL-compatible integration tests with two identities and unauthenticated access.
3. Add owner-scoped persistence/store, sync transport, queue serialization, profile-switch disposal and offline retry tests. Isolate auxiliary local stores.
4. Add auth client/context, Profile screen, explicit guest import, name editing, backup and sync/conflict status. Integrate with workspace boot and deployment variables. Test build and browser guest/unconfigured flow.
5. Provision provider if connected; configure email delivery and public deployment settings. Verify ownership and sync end-to-end where access permits. Review the whole branch, commit, deploy only truthful status, report any remaining provider action.

## Own-backend extension
6. Add validated device-local connection selection, explicit reset, anon version probe, project-scoped sessions/cache/locks, UI and setup instructions. Verify invalid settings fail closed, privileged keys are rejected, the same UUID in two projects is isolated, and default behavior remains available.
