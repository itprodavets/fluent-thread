# Connected learning map

Status: approved by user, 22 November 2026. Implement, preserve manual connections and progress, commit and publish.

## Intent
Turn the editable map into a learning navigator: automatically connect schools, lessons, curated skills and dialogue scenes, open the intended practice directly, and retain the user's own links and layout separately. Preserve all existing learning data and profile separation.

## Approach
Derive automatic relationships from existing topic.source / lessonSource, imported dialogue resources and the curated skill catalog. Extend the current React/SVG editor rather than introduce a second graph library or copy the course catalog into editable user topics. A full unfiltered graph would be unreadable on a phone; a static tree would hide cross-school skill relationships.

## View and navigation
Use four visibly labelled node types: school, lesson, dialogue, skill. Default to a focused neighbourhood of the selected lesson: its school, all its dialogue scenes and the skills actually linked to those scenes. Search/browse schools, lessons, dialogues and skills across the current language; selecting a school shows its lessons, selecting a skill shows matching dialogues and their lesson/school context across schools. Provide an explicit way back to the broader browse/focus view and counts so hidden content remains discoverable.

Group A1–C2 versions of one dialogue into a single scene node within its own lesson, never across different lessons. Reuse dialogueChoices grouping semantics per topic: normalized title for a levelled group, resource ID for an unlevelled scene, and a resource discriminator for duplicate versions of the same level. Renames may leave saved references unresolved; never reconnect by heuristic title similarity. A node detail panel shows its full name, context, available levels and actions. A dialogue's practice action encodes the topic ID, exact resource ID and optional skill ID in the material URL; the selected resource determines the level. Validate resource membership in the current topic/language. A stale resource falls back only within the requested topic with an explanation; preserve legacy lesson URLs. A skill's practice action opens an actually matched scene in skill context. A lesson opens its materials/practice; a school lets the learner inspect its lessons. Navigation must not grade anything as studied.

Automatic edges are derived, labelled and visually distinct from manual edges. They cannot be removed as if they were user data. No semantic guessing: untagged dialogues simply have no skill edge. Missing or unconfirmed schools remain visibly labelled, not asserted as confirmed providers. Retain every existing user topic, including isolated or newly created topics. Derive automatic learning edges only where actual imported resources or source metadata exist; mere public availability must not pretend registration or completed study. Render curated skills only for English, because no other-language skill catalog exists yet. Use exact catalog school/scene matches and leave ambiguous duplicate matches unlinked rather than guessing.

## Editing and storage
Retain drag, keyboard movement, search focus, zoom/reset, toolbar creation and two-tap/handle-drag connection workflows. Let the learner add manual links between visible typed nodes; offer a searchable destination picker for links to nodes outside the current focus. Existing topic-to-topic connections and topic positions remain compatible and authoritative for lesson nodes. Write lesson-to-lesson links exclusively to Topic.connections and lesson positions to Topic.position. The typed overlay owns only links involving another node type and positions for those types; no competing writable stores. Store only new typed-node positions and manual links in a sparse flat learningMap overlay inside existing Study.languages[language] metadata. Use typed dictionary entries (position/edge) with deterministic keys and explicit null deletion markers. The existing languages record is understood and round-tripped by older clients; do not add new profile-sync record groups that older open clients could discard. Scope first-creation object merging to the learningMap dictionary, merge distinct entries independently, and keep explicit null tombstones on concurrent delete-versus-edit. Existing Supabase storage needs no SQL or auth-policy change. Automatic graph data is derived, not copied into cloud storage.

Use namespaced stable IDs: topic IDs for lessons; language + normalized school identity for schools; topic ID + dialogue-group identity for scenes; language + curated skill ID for skills. Manual links have deterministic undirected keys. Reject self, duplicate, cross-language or unknown-target connections. Retain unresolved saved links/positions without applying them to unrelated nodes; deriving or filtering the graph never deletes data. New content updates automatic edges without rewriting user links, words, results or repetition schedules. Reject a new link already represented automatically; if an existing manual link later coincides with an automatic relationship, keep its saved intent and let removing the manual layer leave the automatic relationship visible.

## Implementation boundaries
Use a stable language-wide canvas coordinate frame compatible with existing topic positions; changing focus does not recompute or save existing coordinates. Place generated nodes deterministically around anchors, and scroll/fit to the visible neighbourhood. Bound school and skill expansion to 12 lessons/scenes per page, with discoverable counts and next-page controls. Keep the complete derived graph available for search and the manual-link destination picker. A pure graph builder handles typed nodes/edges, source-backed skill matches, focus/search and preservation helpers. A typed graph canvas handles rendering and gestures; the page owns focus, selection and learning actions while reusing the topic editor. A small material-route helper builds/parses exact practice links and supports existing lesson URLs. Keep graph presentation state out of learning progress and retain all existing local/cloud storage choices.
